        01
        
The Study

      

      

        

          

            Online sportsbooks are financial systems wearing a sports jersey: they hold user
            funds, verify identity, and settle thousands of real-money transactions in real time.
            That makes them a prime target for credential stuffing, account takeover,
            network intrusion, and transaction fraud.
          

          

            This capstone built a complete simulated sportsbook — login interface, betting engine,
            encrypted database, monitoring stack — and ran identical attack campaigns against two
            configurations: a baseline (passwords + basic firewall) and an
            enhanced build (MFA + IDS/SIEM + encryption + fraud monitoring).
            Every scenario ran three times under fixed conditions for reproducibility, and every
            result maps to NIST CSF functions and MITRE ATT&CK techniques.
          

          

            The verdict: no single control is enough. Layered defense transformed the platform's
            security posture across every metric measured.

# StakeLine auth — password + optional TOTP second factor
def authenticate(user, password, otp=None):
    record = db.get_user(user)
    if not record or not bcrypt.verify(password, record.hash):
        return Deny("bad_credentials")
    if record.mfa_enabled:                 # enhanced posture only
        if not otp or not totp.verify(record.secret, otp):
            return Deny("mfa_required")   # stolen password is not enough
    return Grant(session=new_session(record))

            Campaign 1 — Credential Stuffing & Account Takeover.
            Hydra + a Python loop replay a breached credential list against StakeLine's login.
            Run one stolen credential by hand, or launch the full 10,000-attempt campaign.
            Toggle the posture and watch MFA collapse the success rate.
          

          

          

            View the attack script
            
# credential stuffing — replay breach dump against /login
hydra -C breach_dump.txt stakeline.sim http-post-form \
  "/login:user=^USER^&pass=^PASS^:F=bad_credentials"

for user, password in load("breach_dump.txt"):
    r = session.post(LOGIN, data={"user": user, "pass": password})
    if "mfa_required" in r.text:
        log.blocked(user)          # password valid, second factor stops it
    elif r.ok:
        log.compromised(user)      # baseline: account takeover

            Campaign 2 — Network Intrusion.
            A fixed kill chain — reconnaissance, probing, exploitation — runs against the platform's

# Snort rule — flag rapid port sweep (reconnaissance)
alert tcp $EXTERNAL_NET any -> $HOME_NET any ( \
  msg:"RECON aggressive port scan"; flags:S; \
  detection_filter:track by_src, count 20, seconds 5; \
  classtype:attempted-recon; sid:1000021; rev:1; )

            Campaign 3 — Transaction Fraud.
            Compose a withdrawal and score it. The baseline model only checks a static amount
            threshold; the enhanced anomaly model weighs device, location, velocity, and timing.
            Load a preset or run the full labeled batch to see accuracy and false-positive rate.
          

          

          

            View the scoring model
            
# anomaly-based fraud score (enhanced) vs static threshold (baseline)
def score(txn, model):
    if model == "baseline":
        return 100 if txn.amount > 2000 else 0
    s  = 0.006 * min(txn.amount, 5000)     # amount alone can't flag
    s += 25 if txn.new_device else 0        # unrecognized device
    s += 22 if txn.geo_jump   else 0        # impossible travel
    s += 20 if txn.rapid_repeat else 0     # withdrawal velocity
    s += 14 if txn.odd_hour else 0          # 2-5am activity
    s += 16 if txn.new_account else 0      # thin account history
    return min(s, 100)                       # flag when >= 60

        07
        
NIST CSF Alignment

      

      

        

          
Protect

          
Multi-factor authentication hardens identity at the front door — stolen credentials alone no longer open accounts.

        

        

          
Detect

          
IDS + SIEM correlation surfaces scanning, probing, and exploitation in minutes instead of quarters of an hour.

        

        

          
Respond

          
Anomaly-based fraud monitoring blocks unauthorized bets and withdrawals before funds leave the platform.

        

        

          
Recover

          
Centralized transaction logging supports rollback and forensic reconstruction after an incident.

        

      

    


    
    

      

        08
        
What It Proves

      

      
    
        
  1. MFA is non-negotiable — it cut successful credential stuffing to 1/15th of baseline.
    2. 
        
  2. Detection speed is damage control: eleven minutes less dwell time is the difference between an alert and a breach.
    3. 
        
  3. Fraud monitoring is the last line — it catches the attacker who already got in.
    4. 
        
  4. Layered controls outperform any single control; attackers must beat every layer, defenders only need one to hold.
    5. 
        
  5. Alignment with NIST CSF and MITRE ATT&CK turns raw metrics into a defensible, auditable security posture.
    6. 
      

      

        

          
// Limitations

          
Simulated users and traffic can't fully replicate production behavior; the fraud model was statistical rather than ML-based; social engineering and MFA token interception were out of scope.

        

        

          
// Future work
