        01
        
The Study

      

      

        

          

            Online sportsbooks are financial systems wearing a sports jersey: they hold user
            funds, verify identity, and settle thousands of real-money transactions in real time.
            That makes them a prime target for credential stuffing, account takeover,
            network intrusion, and transaction fraud.
          

          

            This capstone built a complete simulated sportsbook — login interface, betting engine,
            encrypted database, monitoring stack — and ran identical attack campaigns against two
            configurations: a baseline (passwords + basic firewall) and an
            enhanced build (MFA + IDS/SIEM + encryption + fraud monitoring).
            Every scenario ran three times under fixed conditions for reproducibility, and every
            result maps to NIST CSF functions and MITRE ATT&CK techniques.
          

          

            The verdict: no single control is enough. Layered defense transformed the platform's
            security posture across every metric measured.

        03
        
The Attacks

      

      

        Three campaigns, each run against both configurations — first with passwords and a firewall,
        then with the full layered stack.
      

      

        

          1
          
Credential Stuffing & Account Takeover

          
10,000 automated login attempts per trial using breached-style credential lists, driven by Hydra and custom Python — measuring compromise rate with and without MFA.

          
T1078 · T1110 · T1098

Network Intrusion

          
A fixed kill-chain of reconnaissance scans, packet probing, and exploitation attempts against the network layer — with Snort/Suricata and Elastic SIEM watching.

          
T1595 · T1539 · T1041

Fraudulent Transactions

          
Payout manipulation and duplicate-withdrawal injection against the betting engine, scored by an anomaly-based fraud detection model on wager and payout behavior.

        06
        
NIST CSF Alignment

      

      

        

          
Protect

          
Multi-factor authentication hardens identity at the front door — stolen credentials alone no longer open accounts.

        

        

          
Detect

          
IDS + SIEM correlation surfaces scanning, probing, and exploitation in minutes instead of quarters of an hour.

        

        

          
Respond

          
Anomaly-based fraud monitoring blocks unauthorized bets and withdrawals before funds leave the platform.

        

        

          
Recover

          
Centralized transaction logging supports rollback and forensic reconstruction after an incident.

        

      

    


    
    

      

        07
        
What It Proves

      

      
    
        
  1. MFA is non-negotiable — it cut successful credential stuffing to 1/15th of baseline.
    2. 
        
  2. Detection speed is damage control: eleven minutes less dwell time is the difference between an alert and a breach.
    3. 
        
  3. Fraud monitoring is the last line — it catches the attacker who already got in.
    4. 
        
  4. Layered controls outperform any single control; attackers must beat every layer, defenders only need one to hold.
    5. 
        
  5. Alignment with NIST CSF and MITRE ATT&CK turns raw metrics into a defensible, auditable security posture.
    6. 
      

      

        

          
// Limitations

          
Simulated users and traffic can't fully replicate production behavior; the fraud model was statistical rather than ML-based; social engineering and MFA token interception were out of scope.

        

        

          
// Future work

          
Machine-learning fraud models, mobile betting attack surfaces, social-engineering campaigns, and cloud-scale environments.
